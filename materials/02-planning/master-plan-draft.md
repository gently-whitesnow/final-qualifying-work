# Черновой мастер-план

## Цель

Подготовить сразу полноценную ВКР с доказательной инженерной частью, а затем без дополнительного исследования извлечь из нее отчет по преддипломной практике и материалы для защиты.

## Базовая стратегия

1. Сначала собрать внешнее глубокое исследование и карту доказательств.
2. Затем закрыть недостающие инженерные доказательства в проекте: код, конфигурацию, тесты, стенд, метрики.
3. Разработку вести в отдельной ветке под ВКР, без интеграции в `main`.
4. После этого собирать текст полной ВКР, а не наоборот.
5. Финальные `.docx` и презентацию делать только из уже подтвержденных материалов.

## Предварительная последовательность

1. Запустить внешнее глубокое исследование по компактному промпту.
2. Положить результат исследования в этот репозиторий.
3. Разобрать исследование на рабочие артефакты:
   - структура глав,
   - список источников,
   - карта доказательств,
   - перечень диаграмм и скриншотов,
   - список недостающих подтверждений.
4. При необходимости доработать `bugget-api` и связанный deploy-контур:
   - multi-instance стенд,
   - межузловая синхронизация,
   - балансировщик,
   - проверка reconnect и cross-node delivery.
5. Собрать доказательную базу:
   - выдержки из кода,
   - схемы,
   - результаты тестов,
   - таблицы сравнения,
   - нагрузочные или функциональные замеры.
6. Сформировать полную ВКР в `.docx` через Documents skill / MCP.
7. Привести ВКР к ГОСТ, шаблону и визуально проверить рендер страниц.
8. На базе ВКР извлечь отчет по практике.
9. Подготовить презентацию через Presentations skill / MCP.
10. Подготовить короткий текст доклада, вероятные вопросы и резервные слайды.

## Что уже точно понадобится

- Не менее 15 источников, лучше 18-20 с запасом.
- Официальные источники по SignalR и масштабированию.
- Несколько книг и учебных изданий по распределенным системам, веб-приложениям и программной инженерии.
- Схема текущей архитектуры и схема целевой архитектуры.
- Таблица сравнения вариантов масштабирования.
- Скриншоты интерфейса и, возможно, схемы пользовательского сценария.
- Подтвержденные результаты тестирования, а не декларативные обещания.
- Изолированная ветка разработки под ВКР.
- Минимальный воспроизводимый стенд для доказательства вклада.

## Открытые подтверждения от пользователя

- Есть ли отдельный шаблон для полной ВКР, кроме шаблонов практики.
- Какое имя ветки использовать для изолированной реализации под ВКР, если не будет заранее созданной ветки.
- Нужно ли сохранять промежуточные отчеты по экспериментам как отдельные Markdown-артефакты внутри репозитория.
